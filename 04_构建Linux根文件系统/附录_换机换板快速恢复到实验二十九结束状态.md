>
> **系列说明**：本篇是恢复手册系列的**第三册**（附录，不参与专栏实验序号编号，放在 `04_构建Linux根文件系统/` 目录末尾备查）——第一册（`01_移植U-Boot/附录_换机换板快速恢复到实验十一结束状态.md`）管 U-Boot 与 SD 卡，第二册（`03_移植Linux内核/附录_换机换板快速恢复到实验二十三结束状态.md`）管第 5 章内核家当，**本册管第 6 章新增的全部家当：两套自制根文件系统、buildroot 源码树、NFS 双目录、板子的启动指向**。前置：第二册的恢复目标（实验二十三结束态）已达成——本册所有步骤都建立在它的基础上。

## 一、先分清换的是什么——第 6 章的"家当账本"

一句话总纲：**两套根都住在 Ubuntu 的 NFS 目录里（网络即所得），buildroot 源码树在 Ubuntu 磁盘上，板子的启动指向在 MMC 环境区**。先对着下表点货，再按场景决定做几步：

| 家当 | 住在哪 | 断电/换机后 | 丢了怎么找回来 |
|---|---|---|---|
| **busybox 根**（`rfs-busybox`） | **Ubuntu** `/home/cnu/nfsboot/rfs-busybox`（NFS 导出） | 换电脑就丢——**第 6 章家当之一** | 整目录打包带走（最省），或重做实验二十五~二十六（约 1 小时） |
| **buildroot 根**（`rfs-buildroot`） | **Ubuntu** `/home/cnu/nfsboot/rfs-buildroot`（NFS 导出） | 换电脑就丢——**第 6 章家当之二** | buildroot 树在就重解包 rootfs.tar（十分钟）；树也没了走本册步骤 1 |
| **buildroot 源码树** | **Ubuntu** `~/Desktop/LINUX-gy/Test2/buildroot-2020.02.6`（`output/` 约 10 GB，**非 git 仓库**） | 换电脑就丢——**最大的一份** | 本册步骤 1（打包带走或按实验二十八重做 1~2 小时） |
| NFS 导出清单 + v2 使能 | **Ubuntu** `/etc/exports` + `/etc/default/nfs-kernel-server` | 换电脑重配 | 本册步骤 2（两条 nano + 重启服务，五分钟） |
| tftpboot 四文件 + tftpd-hpa | **Ubuntu**（第二册步骤 4） | 换电脑重装 | **第二册步骤 4**，本册不重复 |
| 内核源码树（带 .scmversion） | **Ubuntu**（第二册步骤 2，git WORKING 分支） | 换电脑就丢 | **第二册步骤 2**，本册不重复 |
| 板子启动指向 | **MMC** 环境区：`bootargs` 指 `rfs-buildroot`、`bootcmd`=`run mybootnet` | 随卡/随环境走 | 本册步骤 3（三条 setenv） |
| buildroot 根的 root 密码 | 根内 `/etc/shadow`（`123`，实验二十八步骤 4 自定义） | 随根走 | 重做实验二十八步骤 4，或根还在时 `passwd` 重设 |
| 带哈希 uImage 存档 | `/tmp/uImage-with-hash.bak` | **`/tmp` 重启即丢** | 作业检查需要时：临时挪走 `.scmversion` 重编一次即再现，编完放回去 |

| 场景 | 必做步骤 | 可以跳过 |
|---|---|---|
| 只换开发板（电脑与卡不动） | 步骤 3（板侧启动指向）→ 步骤 4（验收） | buildroot 树、NFS 配置全不用 |
| 换电脑，**buildroot 树打包带过来了** | 第二册步骤 1~4 → 本册步骤 1（解包树 + 补 depmod）→ 步骤 2（NFS）→ 步骤 3 → 步骤 4 | 实验二十八的在线下载与首次全量编译 |
| 换电脑，**什么都没带** | 第二册步骤 1~4 → 本册步骤 1 路线 b（重做实验二十八）→ 步骤 2~4 | 无 |
| 只是不小心改坏了 buildroot 根 | 重解包：`rm -rf` 后重新解包 rootfs.tar（**板子正挂着时禁止 rm -rf**，见"避坑"第 1 条） | 其余全部 |

**最容易白做的一件事**：buildroot 根出问题就重跑整场实验二十八。先看第二节判据分清坏在哪一层——根坏了只是"解包"级的事（十分钟），源码树坏了才是"编译"级的事（小时级）。

## 二、恢复目标：实验二十九结束态的验收判据

**一句话**：上电不碰任何键，板子自动完成"tftp 我们的内核 → NFS 挂 `rfs-buildroot` → 无报错登录"，全流程无人值守。

```
上电 → （bootdelay=0，自动跑 bootcmd）→ U-Boot 打印 tftp 两条
  → my_uImage（Image Name: Linux-5.4.31，纯净版）
  → 内核日志滚完 → VFS: Mounted root (nfs filesystem)
  → Starting syslogd/klogd/sysctl/mdev 各 OK，**无 modprobe 报错**
  → Welcome to alientek STM32MP157
  → ATK-stm32mp1 login: root → Password: 123
  → [root@ATK-stm32mp1]:~#            ← myprofile.sh 的 PS1 已生效
```

逐项判据（四条全过 = 实验二十九结束态）：

1. **无人值守点火**：上电到登录提示全程不需要敲任何命令（bootcmd 已指 `run mybootnet`，见本册步骤 3）；
2. **modprobe 三连报清零**：启动日志无 `can't change directory to '/lib/modules'`（`lib/modules/5.4.31/` 在位、modules.dep 已生成）；
3. **debugfs 已挂**：`mount | grep debug` 打出 `none on /sys/kernel/debug type debugfs (rw,relatime)`（行首 `none` 是虚拟文件系统的设备名占位，判据认 `type debugfs`）；
4. **双根可切换**：bootargs 的 nfsroot 指回 `rfs`（busybox 版）再 reboot，能进 `[root@fsmp1a: /]#`（root 无密码）——切回配方见本册步骤 4。

## 三、步骤 1：buildroot 源码树（换电脑才做）

### 路线 a：打包带走（旧机器上执行，十分钟）

```bash
# 【旧机 Ubuntu 侧执行】——排除 output/（10 GB 产物，可重编），
# 保留 dl/（已下载的源码包，新机上省掉半小时到几小时的在线下载）
cd ~/Desktop/LINUX-gy/Test2
tar -jcf buildroot-2020.02.6-work.tar.bz2 \
    --exclude='buildroot-2020.02.6/output' \
    buildroot-2020.02.6
# 产物几百 MB～1 GB 量级（大头是 dl/）；经共享文件夹/网盘带到新机
```

新机恢复：

```bash
# 【新机 Ubuntu 侧执行】
cd ~/Desktop/LINUX-gy/Test2
tar -jxf buildroot-2020.02.6-work.tar.bz2
cd buildroot-2020.02.6
grep -E "BR2_PACKAGE_KMOD=y|BR2_TOOLCHAIN_EXTERNAL_CUSTOM=y" .config   # 配置还在
```

### 路线 b：从零重做（什么都没带才走）

按实验二十八重做步骤 1~5（源码包在 `04_构建Linux根文件系统/`，md5 见其环境表），**但必须补做下面这一步**——它是实验二十九踩坑后追加的动作、实验二十八正文里没有：

```bash
# 【Ubuntu 侧执行】buildroot 源码顶层：
make busybox-menuconfig
#   Linux Module Utilities ---> [*] depmod
#   退出保存
```

**为什么必须补**：buildroot 的 kmod 包默认只装 `libkmod.so` 库、不带 depmod 命令；busybox 默认配置里 depmod 也没开（详见实验二十九步骤 3 的实测存档）。不补这一步，板子上 `depmod` 就是 `not found`、modprobe 第三集报错永远清不了。

> 编译前置：gcc-arm-9.2 工具链在位（第二册步骤 1）、`Toolchain path` 指向 `/usr/local/arm/gcc-arm-9.2-...`、`make` 不带 `-j`、全程联网（dl 缓存能省下载）。

## 四、步骤 2：NFS 目录与服务器（换电脑才做）

```bash
# 【Ubuntu 侧执行】
sudo apt install nfs-kernel-server nfs-common
sudo mkdir -p /home/cnu/nfsboot
sudo nano /etc/exports
#   末尾加一行：
#   /home/cnu/nfsboot  *(rw,sync,no_root_squash,no_subtree_check)
sudo nano /etc/default/nfs-kernel-server
#   末尾加一行（v2 使能——板子 NFS 客户端按 v2 协商）：
#   RPCNFSDOPTS="--nfs-version 2,3,4 --debug --syslog"
sudo /etc/init.d/nfs-kernel-server restart
```

两套根从哪来（二选一或都做）：

```bash
# 【Ubuntu 侧执行】路线 a：旧机把两个根目录整包带走（连权限带符号连接）
#   旧机：cd /home/cnu/nfsboot && sudo tar -jpcf nfsboot-roots.tar.bz2 rfs rfs-buildroot
#   新机解到同一路径：
sudo tar -jpxf nfsboot-roots.tar.bz2 -C /home/cnu/nfsboot/

# 【Ubuntu 侧执行】路线 b：rootfs.tar 重解包（buildroot 树在就十分钟）
cd /home/cnu/nfsboot && rm -rf rfs-buildroot && mkdir rfs-buildroot && tar xf rootfs.tar -C rfs-buildroot
#   ⚠ 板子正挂着这个根时禁止 rm -rf（Stale file handle 僵尸局，见"避坑"第 1 条）
```

本机自测（服务器侧先验，别把配置错误带上板）：

```bash
# 【Ubuntu 侧执行】
sudo mount localhost:/home/cnu/nfsboot/rfs-buildroot /mnt -t nfs
ls /mnt               # bin dev etc lib lib32 linuxrc media mnt opt proc root run sbin sys tmp usr var
sudo umount /mnt
```

## 五、步骤 3：板子侧启动指向（换板/环境乱才做）

SD 卡侧（U-Boot 三件套 + 环境基线）与第二册步骤 5 的六条配方**全部照第二册**，本册不重复。在其完成后，**补上第 6 章的增量三条**：

```text
STM32MP> setenv bootargs 'console=ttySTM0,115200 root=/dev/nfs nfsroot=192.168.0.100:/home/cnu/nfsboot/rfs-buildroot,proto=tcp rw ip=192.168.0.8:192.168.0.100:192.168.0.1:255.255.255.0::eth0:off'
STM32MP> setenv bootcmd 'run mybootnet'
STM32MP> saveenv
```

| 变量 | 值 | 作用 / 依据 |
|---|---|---|
| `bootargs` | nfsroot 指 **`rfs-buildroot`**（实验二十九步骤 1） | 上电默认进 buildroot 根；想进 busybox 根把路径改成 `rfs` 即可 |
| `bootcmd` | **`run mybootnet`**（实验二十九步骤 3 复验时改） | 上电/复位自动点火我们的内核——`STM32MP>` 从此不是必经一站 |
| `mybootnet` / `mybootemmc` | 同第二册步骤 5 | 网络点火 / eMMC 出厂件备胎 |

新板子的网口 MAC、eMMC 盘号认法同第二册；`ip=` 七字段里 client-ip 是**板子**（`.8`）、server-ip 是 **Ubuntu**（`.100`），别写反。

## 六、步骤 4：验收——上电即达 + 双根切换

```text
【板子上】上电/复位，全程不碰任何键：
  自动 tftp → 挂 rfs-buildroot → 登录 root/123 → [root@ATK-stm32mp1]:~#
  # mount | grep debug          → none on /sys/kernel/debug type debugfs ...
  # ls /lib/modules/5.4.31/     → modules.dep / modules.alias / modules.symbols
  # ls /                        → 18 样（含 lib32 media opt run）
```

双根切换（"改根不烧卡"的日常）：

```text
【板子上】进 buildroot 根：bootargs 的 nfsroot 指 rfs-buildroot（本册步骤 3 默认态）
【板子上】切 busybox 根：setenv bootargs 'console=ttySTM0,115200 root=/dev/nfs nfsroot=192.168.0.100:/home/cnu/nfsboot/rfs,proto=tcp rw ip=192.168.0.8:192.168.0.100:192.168.0.1:255.255.255.0::eth0:off' → saveenv → reboot
  → [root@fsmp1a: /]#（busybox 根，root 无密码）——切回 buildroot 根同法反向
```

四条判据全过 + 双根切换各一次 = **恢复到实验二十九结束状态**，第 7 章可直接开跑。

## 七、避坑清单（第 6 章专属，条条实测踩过）

1. **板子挂着根时，禁止在 Ubuntu 侧 `rm -rf` 那个根目录**——板上运行中的系统握着旧句柄，删后一切访问报 `Stale file handle`、shell 僵尸（`reboot` 都执行不了），唯一出路复位键/断电。重部署姿势：先让板子离开根（reboot 拦停进 U-Boot）再删，或 `tar xf` 覆盖式更新不删目录。
2. **重做/迁移 buildroot 树，必补 busybox depmod**（本册步骤 1 路线 b 的附加步）——kmod 只装库、busybox 默认配置无 depmod，漏了它板上 `depmod: not found`、modprobe 第三集报错清不了。
3. **Set UID 位与解包方式绑定**：普通用户 `tar xf` 解包，GNU tar 非 root 不恢复 setuid 位——busybox 上没有 s、课件剧本的 Permission denied 一批不出现（是好事）；若用 `sudo tar` 解包，s 位会回来、报错会重现。两种都属正常，判据是 busybox 以真实 root 身份运行。
4. **`/tmp` 重启即丢**：带哈希 uImage 存档（作业检查用）别放 `/tmp`，要留就挪到家目录或共享目录。
5. **buildroot 根默认无 Qt、无第三方包**——作业要交的 `rfs-buildroot-qt` 是实验三十六（第 10 章）加包重编的产物，本册恢复出的最小根不承担 Qt 交付。
6. **`mount` 输出设备名在前**：debugfs 行是 `none on /sys/kernel/debug type debugfs ...`，验收别等"debugfs 开头"的行。

- `output/images/rootfs.tar` 存在（量级 3.4 MB 上下，含 kmod 约 3.45 MB）
