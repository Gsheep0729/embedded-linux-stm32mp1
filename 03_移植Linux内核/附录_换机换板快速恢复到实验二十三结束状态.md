# 附录 换电脑 / 换板子后，快速恢复到实验二十三结束状态

> **对应课件**：《第3章 移植U-Boot》3.6 节 + 《第5章 移植Linux内核》5.4~5.6 节收官形态的**恢复手册**（本篇无新增 Slide）
>
> **系列说明**：本篇是第 3 章恢复手册（`01_移植U-Boot/附录_换机换板快速恢复到实验十一结束状态.md`）的**续篇**（**附录**，不参与专栏实验序号编号，放在 `03_移植Linux内核/` 目录末尾备查）。换了开发板、换了宿主机、源码树丢了或 SD 卡坏了，用最少步骤恢复到**实验二十三完成时的形态**——也就是**第 6 章全部实验（实验二十四起）可以直接开跑的起点**。实验二十四（根文件系统全景）是认知篇、无板上状态，所以本篇这份状态就是第 6 章一切实验的地基。全篇回答两个问题：**哪些东西住在哪、丢了要怎么找回来**；前一册管 U-Boot 与 SD 卡，本册管第 5 章新增的全部家当。

## 一、先分清换的是什么——第 5 章的"家当账本"

一句话总纲：**U-Boot 与它的"使用状态"在 SD 卡上，出厂件在 eMMC 上，我们编的内核树在 Ubuntu（git 管着），点火产物在 tftp 服务器上**。四样各断各的电源，先对着下表点货，再决定做几步：

| 家当 | 住在哪 | 断电/换机后 | 丢了怎么找回来 |
|---|---|---|---|
| TF-A + U-Boot（trusted 版） | **SD 卡** fsbl1/fsbl2/ssbl 分区（第 3 章烧写） | 保留（随卡走） | 重烧：见第一册附录步骤 3（`u-boot.stm32` 可无限重编） |
| U-Boot 环境变量（bootargs/bootcmd/mybootnet…） | **SD 卡** env 区（sdb4 内，dd 三条不覆盖） | 保留（随卡走） | 本册步骤 5 六条配方重设 |
| 出厂内核 + mipi050.dtb | **板上 eMMC** bootfs 分区 **+** Ubuntu tftp 服务器各一份 | eMMC 里的保留 | 资料 zip `官方系统内核和设备树.zip` 重拷 |
| 出厂根文件系统 | **板上 eMMC** rootfs 分区（p4） | 保留（出厂自带） | ——（出厂自带，坏了可重刷） |
| **我们编的内核 + dtb（源码树）** | **Ubuntu**：`~/Desktop/LINUX-gy/Test2/…/linux-stm32mp-5.4.31-r0/linux-5.4.31`，**git WORKING 分支管着** | **换电脑就丢——第 5 章最大的一份家当** | 本册步骤 2（bundle 恢复或按文档重做） |
| **点火产物**（my_uImage / stm32mp157a-fsmp1a.dtb） | **Ubuntu** tftp 服务器 + 编译产物目录 | 换电脑就丢 | 源码树在就 `make` 重编（几分钟）；源码树也没了先走步骤 2 |
| tftpd-hpa 服务器 | **Ubuntu**（apt 装，systemd 自启） | 换电脑重装 | 本册步骤 4（五分钟） |

| 场景 | 必做步骤 | 可以跳过 |
|---|---|---|
| 只换开发板（卡与电脑不动） | 步骤 5（板子侧环境复位）→ 步骤 6（验收） | 工具链、源码树、编译、tftp 全不用 |
| 换电脑，**源码树用 bundle/压缩包带过来了** | 步骤 1（三套工具链）→ 步骤 3（bundle 恢复 + 重编）→ 步骤 4（tftpd-hpa）→ 步骤 5 → 步骤 6 | 23 个补丁、实验二十~二十二的所有源码改动 |
| 换电脑，**源码树没带** | 步骤 1 → 步骤 2 路线 b（重做实验十九~二十二）→ 步骤 3~6 | 无 |
| 卡坏了 / 全新卡 | 第一册附录步骤 2~4（分区 + 烧 U-Boot + 环境复位）→ 本册步骤 4~6 | 内核树相关（在 Ubuntu，没丢） |
| 只是不小心 `saveenv` 存错了 / 开机行为不对 | 步骤 5 | 其余全部 |

**最容易白做的一件事**：进系统失败就去重烧 SD 卡。第 5 章之后点火走的是 tftp——**SD 卡上只有 U-Boot 和环境变量，没有内核**；先看第二节判据分清坏在哪一层。

## 二、恢复目标：三层判据（先认靶子再动手）

**第一层：U-Boot 层**（与第一册附录完全相同，四条）：

1. TF-A 开场无 `U-Boot SPL` 横幅；`Board: stm32mp1 in trusted mode (st,stm32mp157a-dk1)`；
2. `MMC:   STM32 SD/MMC: 0, STM32 SD/MMC: 1`、`Net:   eth0: ethernet@5800a000`，无 EQOS/电源/ADC 报错；
3. `printenv`：`bootdelay 5`、`ipaddr 192.168.0.8`、`serverip 192.168.0.100`、`ethaddr 1A:1F:DB:0E:69:FD` 在位；
4. autoboot 落回 `STM32MP>`，无出厂 `192.168.202.x` 的 TFTP 残留。

→ 不达标：**第一册附录**步骤 2~4（分区/烧写/环境复位），本篇不重复。

**第二层：内核点火层**（第 5 章新增，本册负责）：

```
STM32MP> run mybootnet
# tftp 两条：my_uImage ≈ 7,315,200 字节、stm32mp157a-fsmp1a.dtb ≈ 63,890 字节
# Image Name: Linux-5.4.31-g<8 位哈希>        ← git 版本串（干净提交后无 -dirty）
# Machine model: HQYJ STM32MP157 FSMP1A Discovery Board   ← 无 MIPI = 我们的 dtb
# 内核日志滚完 → 挂根 → root@fsmp1a:~# 或对应提示符
```

**第三层：出厂系统层**（`run bootcmd` 出厂件组合，验收系统健康）：

横幅 `ST OpenSTLinux - Weston - ... 3.1-snapshot fsmp1a ttySTM0` → `fsmp1a login: root (automatic login)` → `root@fsmp1a:~#`。**看门狗已被 systemd 接管喂狗（32s），进系统后不会被复位**——这是与实验十六 panic 状态最大的行为差异。

版本串认"接力"不认死值，三种都算达标：

| 版本串形态 | 来源 |
|---|---|
| `Linux-5.4.31-g8dd24eeb2` | 干净工作区重编（第 5 章收官态，推荐） |
| `Linux-5.4.31-g381ee3922-dirty` | 实验二十一/二十二改动未提交时的构建（也能用，但建议补提交） |
| `Linux-5.4.31`（无哈希） | 出厂内核（`run bootcmd` 时）——**别当成自己的** |

## 三、步骤 1：备料（换电脑先看这节）

### 1.1 两棵源码树的迁移——第 5 章最大的家当

**U-Boot 树与内核树都是本地 git 仓库，换电脑前务必打包带走**（在旧机器上执行，两棵树各一条）：

```bash
# 内核树（在 ~/Desktop/LINUX-gy/Test2/…/linux-stm32mp-5.4.31-r0/ 里）：
cd …/linux-stm32mp-5.4.31-r0/linux-5.4.31
git bundle create ~/linux-5.4.31-fsmp1a.bundle --all      # 全部分支与历史打进一个文件
# U-Boot 树同理：
cd …/u-boot-stm32mp-2020.01
git bundle create ~/u-boot-fsmp1a.bundle --all
```

新机器恢复（bundle 里带全部提交，工作区改动**不在 bundle 里**——未提交的改动要先 `git stash list` 查一遍、有就 `git diff > /tmp/wip.patch` 另存）：

```bash
git clone linux-5.4.31-fsmp1a.bundle linux-5.4.31 && cd linux-5.4.31
git checkout WORKING        # bundle 里带分支名，切回工作分支
```

没做 bundle、树丢了？→ 走本册步骤 2 路线 b（按实验十九~二十二重做，全部有指导，约 2~3 小时）。

## 五、步骤 3：编译 + 产物对账

```bash
cd "$KTOP"      # 或 cd <共享目录>/stm32mp1-…/linux-5.4.31
make uImage dtbs LOADADDR=0xC2000040
ls -l arch/arm/boot/uImage arch/arm/boot/dts/stm32mp157a-fsmp1a.dtb
# uImage ≈ 7,315,200 字节量级（Data Size + 64 头）；dtb ≈ 63,890 字节量级（含 sdmmc2/ethernet0 两节点）
# 版本串 = Linux-5.4.31-g<当前 HEAD 哈希>；工作区干净则无 -dirty
# 与历史数值有出入属正常——编译时间戳与路径都会影响；对账认"能点火 + Machine model 无 MIPI"
```

## 六、步骤 4：tftpd-hpa 服务器 + tftpboot 四文件

```bash
sudo apt install tftpd-hpa
sudo nano /etc/default/tftpd-hpa     # 四行：TFTP_USERNAME/TFTP_DIRECTORY/TFTP_ADDRESS/:69/TFTP_OPTIONS="-l -c -s"
sudo service tftpd-hpa restart && sudo service tftpd-hpa status    # active (running)
sudo mkdir -p /home/cnu/tftpboot
SRC=<共享目录>/stm32mp1-…/linux-5.4.31
cp $SRC/arch/arm/boot/uImage /home/cnu/tftpboot/my_uImage
cp $SRC/arch/arm/boot/dts/stm32mp157a-fsmp1a.dtb /home/cnu/tftpboot/
cp <共享目录>/官方系统内核和设备树解压目录/uImage /home/cnu/tftpboot/uImage          # 出厂内核（步骤"出厂件点火"用）
cp <共享目录>/官方系统内核和设备树解压目录/stm32mp157a-fsmp1a-mipi050.dtb /home/cnu/tftpboot/
chmod 644 /home/cnu/tftpboot/*
ls -l /home/cnu/tftpboot             # 四文件在列、权限 644
```

> tftpd-hpa 是 systemd 服务，**装完即开机自启**，换电脑重启后不用手动拉起；`systemctl status` 一眼确认。

## 七、步骤 5：板子侧环境恢复（换板子/环境乱了才做）

SD 卡侧（U-Boot 三件套 + 分区 + 烧写 + `env default -a` 清遗留 + 基线四条）**全部照第一册附录步骤 2~4**，本册不重复。第一册做完后，**补上第 5 章的增量四条**：

```
STM32MP> setenv bootargs 'console=ttySTM0,115200 root=/dev/mmcblk2p4 rootwait rw'
STM32MP> setenv mybootnet 'tftp c2000000 my_uImage;tftp c4000000 stm32mp157a-fsmp1a.dtb;bootm c2000000 - c4000000'
STM32MP> setenv mybootemmc 'ext4load mmc 1:2 c2000000 uImage;ext4load mmc 1:2 c4000000 stm32mp157a-fsmp1a-mipi050.dtb;bootm c2000000 - c4000000'
STM32MP> setenv bootcmd 'tftp c2000000 uImage;tftp c4000000 stm32mp157a-fsmp1a-mipi050.dtb;bootm c2000000 - c4000000'
STM32MP> saveenv
STM32MP> saveenv
```

| 变量 | 值 | 作用 / 依据 |
|---|---|---|
| `bootargs` | `console=ttySTM0,115200 root=/dev/mmcblk2p4 rootwait rw` | **盘号以点火日志实录为准**（出厂 dtb 下实测 eMMC=mmcblk2；自己的 dtb 无 mmc 别名，按探测顺序可能挪位） |
| `bootcmd` | 出厂文件名三连 | `run bootcmd` = 出厂内核点火（第 10 章 GUI 用） |
| `mybootnet` | 自己的 `my_uImage` + `stm32mp157a-fsmp1a.dtb` | `run mybootnet` = 自己的内核点火（第 5 章日常） |
| `mybootemmc` | eMMC bootfs 出厂件（ext4load，不走网络） | 网线不在时的备胎 |

新板子的 eMMC **盘号可能挪位**（`mmcblk1/2` 是探测顺序）：点火日志里认"3.69 GiB 004GA0 + p1~p5"那颗，`root=` 跟着它写。

## 八、步骤 6：验收——两条点火都要过

```
STM32MP> run mybootnet
# 判据：Machine model = HQYJ STM32MP157 FSMP1A Discovery Board（无 MIPI）→ 挂根 → 命令行
STM32MP> reboot        # 回 U-Boot（停在命令行超 32 秒不会被复位——systemd 已接管喂狗）
STM32MP> run bootcmd
# 判据：出厂内核（oe-user 串）→ Weston 横幅 → root@fsmp1a:~#（第 10 章 GUI 用这条）
```

两条都过 = **恢复到实验二十三结束状态**，第 6 章可直接开跑。

## 九、换电脑 / 换板子必看的增量三件事

1. **串口 COM 号、VMware 三网卡、ASIX 网卡认法**——与第 3/4 章完全相同，见第一册附录第八节，本篇不重复；
2. **`.scmversion` 还没建**（那是第 6 章实验二十七的活）——所以点火 `Image Name:` 带 `g<哈希>` 是正常现象，第 7 章加载模块前内核与模块的版本串必须一致；
3. **板子 LCD 的两种表现要分清**：`run mybootnet`（我们的内核）屏不亮是**预期行为**（没编显示驱动），`run bootcmd`（出厂内核）屏才亮——第 10 章之前所有"看板子反应"的实验都走串口判断。

## 十、白做的清单（第 5 章增量）

- **不要重烧 SD 卡上的 U-Boot**——它没变过（除非第一册判据不过）；
- **不要重打 23 个补丁**——git 历史里全有（bundle 恢复或按文档重做均可，但别用"重新解压再 patch"覆盖一棵干净的树）；
- **不要手改 `.config`**——配置固化在 `stm32_fsmp1a_defconfig`，改动走 menuconfig → `cp .config arch/arm/configs/…` 路线；
- **不要在出厂系统里改文件**——借来的根，改了也会在下次重刷时丢。

## 十一、恢复完成标志

- 两棵源码树 `git log --oneline -1` = U-Boot `e97b6818`、内核 `8dd24eeb2`，`git status --short` 均无输出

- `make uImage dtbs LOADADDR=0xC2000040` 产物字节数在 7,315,200 / 63,890 量级（版本串与时间戳不同会微调）

- `run bootcmd`：出厂内核点火、Weston 横幅、自动登录 root——两条点火都过 = 恢复完成
