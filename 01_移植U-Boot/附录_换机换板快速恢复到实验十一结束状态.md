# 附录 换电脑 / 换板子后，快速恢复到实验十一结束状态

> **对应课件**：《第3章 移植U-Boot》3.6 节，Slide 82-87（实验十一收官形态的**恢复手册**，本篇无新增 Slide）
>
> **系列说明**：本篇是第 3 章的"重来一遍"手册（**附录**，不参与专栏实验序号编号，放在 `01_移植U-Boot/` 目录末尾备查）。换了开发板、换了宿主机、卡丢了或格式化了，用最少步骤把板子恢复到实验十一的完成形态——也就是**实验十二以及第 4 章全部实验可以直接开跑的起点**。全篇只回答一个问题：哪些事必须重做，哪些事其实已经躺在 git 和卡上、根本不用碰。

## 一、先分清换的是什么，决定要做几步

一句话总纲：**驱动与配置在 git 里，启动镜像在卡上，"使用状态"在环境变量里。** 换板子只动第三样，换电脑要重做第二样，全新卡三样都做。

| 场景 | 必做步骤 | 可以跳过 |
|---|---|---|
| 只换开发板（同一张卡、同一台电脑） | 步骤 4（板子侧环境复位）→ 步骤 5（验收） | 分区、编译、烧写全部不用 |
| 换电脑 / 新虚拟机，源码树与 git 带过来了 | 步骤 1（装工具链）→ 步骤 3（重编 + 烧写）→ 步骤 4 → 步骤 5 | menuconfig（三站四处已在 defconfig 里）、驱动改动 |
| 全新 / 来路不明的 SD 卡 | 步骤 1 → 2 → 3 → 4 → 5 全走 | 无 |
| 卡还能进命令行，只是开机行为不对 | 步骤 4 | 其余全部 |

**最容易白做的一件事**：换了板子就去重新编译烧写。先看第二节判据——如果 `in trusted mode`、`MMC: 0, 1`、`Net: eth0` 三行都在，卡上就是对的，只需处理环境。

## 二、恢复目标：四条判据（先认靶子再动手）

上电后串口日志依次满足：

1. **TF-A 开场**：`NOTICE: BL2: v2.2-r1.0(debug):a70053f` / `INFO: SP_MIN: ...`，**没有** `U-Boot SPL` 横幅；
2. **U-Boot 横幅后**：`Board: stm32mp1 in trusted mode (st,stm32mp157a-dk1)`；
3. **成果全线保持**：`MMC:   STM32 SD/MMC: 0, STM32 SD/MMC: 1`（F-6）、`Net:   eth0: ethernet@5800a000` 且**无** `EQOS_DMA_MODE_SWR stuck`（F-5）、无电源报错（F-1）、无 ADC 报错（F-3）；
4. **环境是自己那套**：autoboot 走 `Boot over mmc0!` → `** Unrecognized filesystem type **` → 停 `STM32MP>`。**只要看到 `TFTP from server 192.168.202.x`，就是出厂遗留环境还在位**，走步骤 4。

版本串认"接力"不认死值，两种都算达标：

| 版本串 | 来源 |
|---|---|
| `2020.01-stm32mp-r1-g88f08870-dirty (Sep 19 2026 - 14:51:04 +0800)` | 从旧机器直接拷来的那次构建产物（实验十一当时的镜像） |
| `2020.01-stm32mp-r1-ge97b6818 (较新时间戳)` | 新机器上重编：工作区已干净、`??` 已清零，所以**不带 `-dirty`**，哈希 = trusted 收官提交 |

## 三、步骤 1：备料（换电脑先看这节）

### 1.1 源码树 + git

F-1~F-6 六个提交与 trusted 收官提交全在版本库里，**换机器不需要重做任何一处驱动或设备树改动**。两条自检：

```bash
cd <你的>/u-boot-stm32mp-2020.01-r0/u-boot-stm32mp-2020.01
git log --oneline -1     # 期望 e97b6818 (HEAD -> WORKING) trusted: 新增 FS-MP1A trusted 版 defconfig
git status --short       # 期望无输出（工作区干净）
ls configs/stm32mp15_fsmp1a_*    # 期望两个：basic 与 trusted
```

### 1.2 交叉编译工具链

新虚拟机要按实验一重装：SDK 安装脚本装到**默认目录** `/opt/st/stm32mp1/3.1-openstlinux-5.4-dunfell-mp1-20-06-24`（安装脚本是长名字的 `st-image-weston-*.sh`，不是 `install.sh`；目标目录直接回车用默认值——共享文件夹不支持符号链接），并建好 `/stm32env` 软链接。每个新终端都要激活：

```bash
source /stm32env
echo $CC        # 输出 arm-ostl-linux-gnueabi-gcc ... 才算激活成功
```

没激活就 make 会报 `cc1: error: bad value ('generic-armv7-a') for '-mtune=' switch`——那掉的是 x86 宿主机 gcc。

### 1.3 两份二进制素材

| 文件 | 大小 | 从哪来 | 丢了怎么办 |
|---|---|---|---|
| `tf-a-stm32mp157a-fsmp1a-trusted.stm32` | 241984 字节 | 资料包 `D:\桌面文件\资料\嵌入式linux`；仓库 `01_移植U-Boot/` 目录里另备了一份（`.gitignore` 已忽略，不入库、只备磁盘） | **唯一不能从 git 恢复的东西**：得从出厂资料包或同学机器拷 |
| `u-boot.stm32` | 855605 字节（旧那次构建） | 旧机器源码顶层拷过来，**或**按步骤 3 重编 | 可无限重编，不怕丢 |

## 四、步骤 2：SD 卡分区（换板子不必做，换卡才做）

读卡器经 VMware「虚拟机 → 可移动设备」连给虚拟机，先认准设备号：

```bash
lsblk                                   # 确认 SD 卡是 /dev/sdb（以实际为准，别照抄）
sudo umount /dev/sdb*                   # 有挂载就全卸掉
sudo sgdisk -Z /dev/sdb                 # 清场：输出 GPT data structures destroyed!
sudo partprobe /dev/sdb                 # 刷内核视图，/dev/sdb1~5 此时应消失
```

一条命令建 5 分区（分区名是 ROM 代码找分区的依据，一字不能错）：

```bash
sudo sgdisk --resize-table=128 -a 1 -n 1:34:545 -c 1:fsbl1 -n 2:546:1057 -c 2:fsbl2 -n 3:1058:5153 -c 3:ssbl -n 4:5154:136225 -c 4:bootfs -n 5:136226 -c 5:rootfs -A 4:set:2 -p /dev/sdb -g
```

判据：`lsblk` 里 `sdb1` 256K、`sdb2` 256K、`sdb3` 2M、`sdb4` 64M、`sdb5` 占满其余；名字 `fsbl1 / fsbl2 / ssbl / bootfs / rootfs`。

## 五、步骤 3：编译 + 烧写

**不用再进 menuconfig。** 实验十一收尾时把改好的 `.config` 固化进了 `configs/stm32mp15_fsmp1a_trusted_defconfig`（F-1 关 PMIC_STPMIC1、F-3 关 CMD_ADC 与 ADC、F-5 开 PHY_MAXIO 三站四处都在里面），所以加载它 = 直接复现收官配置：

```bash
source /stm32env
make stm32mp15_fsmp1a_trusted_defconfig
make -j2 all DEVICE_TREE=stm32mp157a-fsmp1a
ls -l u-boot.stm32                      # 期望 855605 字节（配置未动时字节数一致）
```

trusted 配置下**没有** `u-boot-spl.stm32`，产物只有 `u-boot.stm32`。烧写三条 + 弹出：

```bash
lsblk                                  # 再确认一次 /dev/sdb
sudo dd if=tf-a-stm32mp157a-fsmp1a-trusted.stm32 of=/dev/sdb1 conv=fdatasync
sudo dd if=tf-a-stm32mp157a-fsmp1a-trusted.stm32 of=/dev/sdb2 conv=fdatasync
sudo dd if=u-boot.stm32 of=/dev/sdb3 conv=fdatasync
sudo eject /dev/sdb
```

| 分区 | trusted 烧的内容 |
|---|---|
| sdb1（fsbl1）/ sdb2（fsbl2） | 出厂 TF-A，两份互为备份 |
| sdb3（ssbl） | `u-boot.stm32`（**不是** `u-boot.img`） |

想回 basic 版：`make stm32mp15_fsmp1a_basic_defconfig` → `make -j2 all DEVICE_TREE=stm32mp157a-fsmp1a` → 重烧三条 basic 镜像（`u-boot-spl.stm32`→sdb1/sdb2、`u-boot.img`→sdb3）。

## 六、步骤 4：板子侧清掉出厂遗留环境（换板子时真正的必修项）

### 4.1 为什么"卡没变"也会冒出 TFTP

`Loading Environment from MMC... OK` 说明读到了一个 CRC 合法的环境块——但**它不在 sdb1/sdb2/sdb3 三条 dd 覆盖的范围内**（出厂镜像残留的环境区、或板载 eMMC 里出厂 U-Boot 存的那份），所以换板子、换卡之后它会带着出厂那一套回来：

```
serverip 192.168.202.6 / ipaddr 192.168.202.100 / bootdelay 0
bootcmd = tftp uImage + tftp stm32mp157a-fsmp1a.dtb + bootm
```

后果是：倒计时 0 来不及按键 → 直奔 TFTP → 网线没通就 `Waiting for PHY auto negotiation ... No link` → `ARP Retry count exceeded` / `Abort` → `Wrong Image Format for bootm command`。这不是烧写或驱动出问题，是**环境不是你的**。解法就一次 `env default -a`。

### 4.2 命令名：`setenv` 与 `env set` 是一回事

上电（或按复位）后**看准 `Hit any key to stop autoboot` 立刻连按 Enter**；实在拦不住就让它跑完 TFTP 失败落回 `STM32MP>`，或按 Ctrl+C 掐断（`user interrupt!` / `No link` / `FAILED: 0` 都是正常回显）。进了命令行先敲一条 `help` 把命令表看全：

```
STM32MP> help
```

**实际执行结果**（换板后 trusted 版实测）：环境变量这一族四条全在——

```
env       - environment handling commands
printenv  - print environment variables
saveenv   - save environment variables to persistent storage
setenv    - set environment variables
```

手敲 `setenv`（不带参数）也正常打出用法 `setenv [-f] name [value ...]`。**结论：课件的 `setenv` / `printenv` / `saveenv` 在我们这版上直接可用**，本篇配方一律用这套老名字；`env set` / `env print` / `env save` / `env default` 是同一段代码（`cmd/nvedit.c`）的另一套门牌，两者随时可互换。

> **踩过的坑：`Unknown command 'setenv'` 不等于命令没编进来。** 换板当天第一次敲 `setenv` 就吃了这句报错，当时按"trusted 版配置裁剪了命令集"解释——后来三条证据把它推翻了：① `help` 列表里 `setenv` 明明在；② 手敲同一个词正常出用法；③ `.config`（trusted）与 `configs/stm32mp15_fsmp1a_basic_defconfig` 里环境变量相关开关**逐条同值**（`CONFIG_CMD_SAVEENV=y`、`CONFIG_CMD_ENV_EXISTS=y`、`CONFIG_CMD_NVEDIT_INFO=y`），而且这套源码里根本没有 `CMD_SETENV` / `CMD_PRINTENV` 这两个符号，`setenv` 的注册（`cmd/nvedit.c` 1499 行 `U_BOOT_CMD_COMPLETE(setenv, ...)`）外面也没有独立开关可关。真正的病根是**粘进串口的字节**：U-Boot 取命令词时只跳空格和制表符，零宽字符、BOM、全角空格会跟着 `setenv` 一起变成命令名，终端不回显、看着一切正常，U-Boot 却报 `Unknown command 'setenv'`。
>
> 所以排查顺序是：**手敲一遍 → `help` 查列表 → 才怀疑配置**。终端粘贴只用右键（MobaXterm 里 Ctrl+V 不生效），别从 PDF、网页、聊天窗口直接拷命令——这也顺带给第 3 章 basic 版那次"`printenv` 未编入"的记录打上问号：两边配置同值，那次报错很可能同因，留待回切 basic 版时复验。

### 4.3 恢复配方（六条，顺序不能乱）

```
env default -a
setenv bootdelay 5
setenv ipaddr 192.168.0.8
setenv netmask 255.255.255.0
setenv ethaddr 1A:1F:DB:0E:69:FD
saveenv
saveenv
reset
```

| 变量 | 值 | 作用 / 依据 |
|---|---|---|
| `bootdelay` | `5` | 把倒计时从 0 改回来，才拦得住 autoboot（实验十二要练的就是它） |
| `ipaddr` | `192.168.0.8` | 与实验九/十三的 PC 侧 `192.168.0.100` 同网段 |
| `netmask` | `255.255.255.0` | 同上 |
| `ethaddr` | `1A:1F:DB:0E:69:FD` | 课件用的 MAC；首字节 `1A` 的第 2 位为 0 = locally-administered，能过 `m` 标志校验 |
| `bootcmd` | 不手动设 | `env default -a` 之后回落成默认 `run distro_bootcmd`，即 `Boot over mmc0!`，出厂 TFTP 就此消失 |

（清环境用的 `env default -a` 只有子命令写法，没有对应的老名字，所以第一条与后面四条老名字混用——不是笔误。）

三条纪律：

1. **必须先 `env default -a` 再设 ethaddr**。出厂环境里 ethaddr 带 `mo` 双标志（`m` 格式校验、`o` write-once 已有值不许覆盖），直接重设会被拒。`env default -a` 把整套遗留一并清空，才写得进去；若仍报 flags 相关拒绝，用 `env default -a -f`（force）。
2. **`env default -a` 之后可能报** `invalid MAC address in OTP 00:00:00:00:00:00` + `Error: ethernet@5800a000 address not set.`——环境里没 ethaddr 的预期现象，补设即消。
3. **`saveenv` 敲两次**：主副本与冗余副本各刷一份（会打印 `Writing to MMC(n)` 与 `Writing to redundant MMC(n)`）。**把 n 记下来**：`0` = SD 卡，`1` = 板载 eMMC。新板子上这个值可能和旧板不同，值得备查。

`printenv` 复核一遍四个变量都在，即恢复到实验九那套基线；`reset` 重放一次日志，回到第二节判据。

## 七、步骤 5：验收

```
printenv         # 四个变量在位、bootcmd 为默认 distro_bootcmd
reset            # 重放启动日志，对第二节四条判据
```

可选的网络复核（**实验十三的前置，本篇不做也算达标**）：接好网线、PC 侧网卡手动配 `192.168.0.100 / 255.255.255.0`，板子 `ping 192.168.0.100`，期望 `Waiting for PHY auto negotiation to complete..... done` + `host 192.168.0.100 is alive`。Windows 防火墙会拦 ICMP，ping 不通先查防火墙和"网线插的到底是哪块网卡"。

## 八、换电脑 / 换板子必看的三件事

1. **串口 COM 号会变**。`COM11` 是旧机器上板载 ST-Link 虚拟串口的实测值；新电脑上大概率是另一个号，且要装 ST-LINK 驱动设备管理器里才看得到它。MobaXterm 的 Serial 会话重指一次即可，波特率仍是 115200。
2. **新板子的 eMMC 里是出厂系统，留着别动**。实验十四要靠 `mmc dev 1` + `mmc info` + `mmc part` 给它摸底（新板子的 Manufacturer ID / Name / 容量与旧板不一定相同，得重新记录），实验十六还要用它当"能跑起来的 Linux"的参照。红线：`mmc write` / `mmc erase` / `mmc hwpartition` 属于不可逆操作，认命令不动手。
3. **ethaddr 每块板补一个**。两块板不会同时上网，沿同一个值无妨；想区分就改最后一字节（保持首字节第 2 位为 0）。

4. **新电脑上的 VMware 网络要按《1. 开发环境搭建-Linux系统安装》重配一遍**：网卡 1 仅主机 VMnet1（`192.168.56.0/24`，Ubuntu `192.168.56.101`、不填网关）、网卡 2 NAT 上外网；虚拟网络编辑器里 **VMnet1 的类型必须是"仅主机模式"**，「将主机虚拟适配器连接到此网络」与「使用本地 DHCP 服务」两个勾必须常开——改错这一行（实测那次是 VMnet1 被改成了桥接、勾也没了），Windows 那块 VMnet1 适配器会被整个删除，`\\192.168.56.101` 映射的网络硬盘（Z: 盘）当场掉；若 VMnet0 那一行也跟着不见了或整体改乱，点左下「还原默认设置(R)」重建三件套（驱动文件都在，不用重装 VMware）。另外**机器上往往有两块 USB 网卡，一律按驱动描述认**：接板子的看 `ASIX USB to Gigabit Ethernet Family Adapter`，`Realtek USB 2.5GbE` 那类是上外网的口，别改错（"以太网 N"的编号会随插拔变化）。第 4 章实验十三起要**用「添加(A)...」加第三块网卡**（自定义 → VMnet0），点「确定」后看 `.vmx` 里有没有 `ethernet2` 才算落盘，细节见那一篇步骤 3。

顺带两条环境类提醒：读卡器经 VMware 菜单连给虚拟机，`sudo eject` 后可能从虚拟机掉线，下次烧写前重连；拨码仍是 `101`（选 SD 卡启动，FSBL 是 SPL 还是 TF-A 与它无关），断电插卡再上电。

## 九、注意事项：这些是白做的

- **没有"再烧一遍 F-5 驱动"这回事**。F-1~F-6 全是源码级改动，编译进 `u-boot.stm32`；板子同型号（FS-MP1A / STM32MP157A），换板不改变任何驱动需求。判据看第三节日志，不是看资料包里有没有驱动文件。
- **不需要重新分区**。分区表只在换卡/卡被外部工具破坏时才需要重建；换板子与分区无关。
- **不要手改 `configs/` 下那两个 defconfig**。它们是"一键复原"的本体，改动一律走 menuconfig → `cp .config configs/...` 的固化路线。
- **版本串的 `-dirty` 语义**（本版 U-Boot 实测）：未跟踪文件也算 dirty，被 `.gitignore` 忽略的不算。所以收官提交之后重编，应当是一个干净的新哈希。

- `git log --oneline -1` = `e97b6818`，`git status --short` 无输出（换电脑时自检）
- `source /stm32env` + `echo $CC` 出 ARM 编译器（换电脑时自检）
- `lsblk` 五分区名 `fsbl1/fsbl2/ssbl/bootfs/rootfs`，尺寸 256K/256K/2M/64M/其余（换卡时自检）
